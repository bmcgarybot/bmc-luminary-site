# BMC Managed Marketplace Standard

BMC is not intended to be a stationary directory that forwards form emails.

## Customer lifecycle
new request
→ validated
→ qualified
→ matched
→ provider offered
→ provider accepted
→ customer/provider connected
→ estimate/appointment
→ job won or lost
→ BMC monetization event
→ follow-up / repeat-service opportunity

## Provider lifecycle
prospect
→ researched
→ outreach
→ applied
→ screened
→ pilot
→ active
→ paused / suppressed

## BMC service layer
For every service front BMC should eventually provide as many of these as the category supports:
- structured intake
- scope clarification
- local provider matching
- territory/capacity filtering
- provider accept/decline
- rerouting on decline/no-response
- appointment/estimate coordination
- status follow-up
- win/loss tracking
- review/quality feedback
- repeat-service reminders
- recurring-maintenance scheduling
- buyer/vendor history
- payment/lead-fee/subscription tracking
- exception handling

## Marketplace rule
The public page is only the front door. The product is the managed workflow behind it.

## Monetization models
Different niches can use different models:
- qualified lead fee
- accepted-lead fee
- booked appointment fee
- won-job fee
- monthly territory subscription
- recurring route referral
- buyer sourcing fee
- fixed research product
- maintenance concierge subscription
- brokerage/referral fee where lawful
- savings-share where contractually appropriate

## Initial provider routing
1. Exact service + exact declared market.
2. Active/pilot providers only.
3. Respect capacity/minimum-job filters when data exists.
4. Rank by quality score, response rate, proximity/territory fit, and recency.
5. Offer to one or a small controlled group depending monetization model.
6. Expire unanswered offer.
7. Re-route.
8. Escalate to exception when no eligible provider remains.

## No fake marketplace rule
Do not display vendor counts, “available now,” review scores, savings, response times, or booking claims unless the backend has real data supporting the claim.
